# 实验设计：一次全程留痕的 AI 协作开发实验

本仓库的产品是载体，实验是第二产品。先定口径，再收数据——本文件在写第一行业务代码之前定稿，防止事后编数。

## 研究问题

- **RQ1（效率）**：与估算的纯手写基线相比，AI 协作把功能交付速度提升多少？
- **RQ2（质量）**：AI 生成代码的缺陷率多高？缺陷集中在哪类问题？什么门禁拦住了它们？
- **RQ3（边界）**：哪些环节交给 AI 是安全的，哪些必须人来？依据是什么？

## 测量口径

| 指标 | 定义 |
|---|---|
| 功能点 | 一个可向他人演示的完整行为 = 1 功能点 |
| 效率基线 | 任务拆解后按自己历史手写速度逐项估时求和（**估算值，如实标注**） |
| 缺陷 | 被编译门禁 / 单测 / 人工审查 / 自用发现的任何问题，按**发现渠道**分类 |
| AI 参与度 | commit 尾注 `Authorship: ai/mixed/human` 的行数占比（git log 可复核） |
| 成本 | ZCode 与 LLM API 的 token 消耗（各后台可查） |

## 数据采集流程

每个开发 session 结束花 5 分钟填 `METRICS.md` 一行；AI 出错当天进 `AI-FAILURES.md`；技术决策当场进 `DECISIONS.md`。

## 版本计划与验收标准（验收人是自己——真实用户）

| 版本 | 内容 | 验收标准 |
|---|---|---|
| v1 | 文本模拟面试：输入岗位描述 → 一轮约 10 题 → 评估报告 | 本人完整用一次，且愿意用第二次 |
| v2 | RAG 针对性：简历 + JD 入库，出题贴合个人背景 | 同一岗位 v1/v2 出题对比，针对性可感知提升 |
| v3 | 语音模拟面试 | 真实跑通一次完整语音模拟 |
| v4 | 薄弱点画像 + 复习计划 + 数据面板 | 面板实际指导了第二天的复习安排 |

## 已知局限（诚实声明，面试时主动讲）

无对照组，基线是估算，样本量 n=1。这是一次工程观察而不是学术实验；它的价值在于口径诚实、全程可追溯、结论有一手数据支撑。
